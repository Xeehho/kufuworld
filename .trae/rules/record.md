# 需求变更自动记录规则

每次需求开发完成后，**必须**自动将本次新增/修改内容总结并追加到 `.trae/gameWork.md`，无需用户提醒。

## 一、记录目的

用户需要通过 `.trae/gameWork.md` 随时回看历史改动内容。该文件会持续变大，属于本地工作日志。 

## 二、执行时机（强制）

- 一个需求完成（代码修改完毕、校验通过）后**立即**写入，不等用户要求
- 同一会话中的多个需求，逐条独立记录

## 三、日期规则（强制）

- 每条记录标题的日期 = **该任务实际完成当天的日期**
- 写记录前**必须**先执行 `Get-Date` 获取真实系统时间，**禁止**直接使用会话上下文中的日期（跨天会话会过期）
- 跨天会话补记/修正时，用 `git log --since/--until` + `git show --stat` 按提交涉及文件区分每条任务的实际完成日期

## 四、记录格式（模板）

```markdown
### YYYY-MM-DD 需求一句话标题
- 文件：`涉及文件1`、`涉及文件2`
- 改动内容：做了什么、为什么（一两句话说清）
- 实现：关键实现方式/判断逻辑/新增 i18n key 等(可选)
```

- 新记录插入到**对应功能点分组的最上方**（新→旧排序）
- 文件路径写相对仓库根目录的路径

## 五、组织规则

- 按「功能点/模块」设二级标题分组（如 `## 首页文章详情页`），相同功能点的改动归入同一组
- **每个功能点分组最多保留 30 条记录**，超出时自动删除该组最旧的记录
- 禁止重复记录：同一需求的后续微调，更新该需求已有记录，不新增条目

## 六、禁止事项

- **禁止**将 `.trae/gameWork.md` 提交到 git 或打包上传（确保已被 `.gitignore` 忽略；提交代码时不得 `git add` 该文件）
- **禁止**在 gameWork.md 中记录需求无关内容（如闲聊、临时调试）
- **禁止**修改或删除未过期的历史记录（用户要回看全部历史）
