# 开发完成自动保存与续跑规则（ZCode）

> 用户 2026-09-05 拍板：开发完成后**不等用户指令**，自动走「保存 → 提交 → 续跑下一阶段」流程。

## 一、开发完成时（强制自动执行，无需用户提醒）

一个需求/里程碑完成（代码改完、验证通过、`.zcode/gameWork.md` 已按《需求变更自动记录规则》记录）后，自动依次执行：

1. **自动调用「保存代码zcode」技能**——按本次会话全部改动总结 commit，提交到当前分支（feat），协作署名由技能自带（Co-authored-by: GLM <noreply@z.ai>）；
2. **自动调用「提交代码zcode」技能**——多条记录压缩合并到需求分支；该技能自带的"是否推送远程"选择环节**保留交互**，推送永远经用户确认，禁止静默推送；
3. **自动续跑下一阶段**——按交接文件/设计文档的里程碑顺序直接开工下一阶段，开工即同步滚动更新：
   - `.zcode/tasks/<slug>.md`（已完成/未完成清单，按《长任务交接规则》）
   - `.zcode/gameWork.md`（新阶段完成后照常记录）

## 二、上下文即将满时（强制）

- 收到上下文压缩/总结提示，或判断剩余窗口装不下下一阶段工作量时：**立即**按《长任务交接规则》做一次完整交接更新（已完成/未完成/关键决策/现场），然后**明确告知用户**："上下文将满，请开新窗口说『继续XX任务』"；
- **新窗口由用户手动开启**——AI 无法自行创建新会话，这一步永远需要用户操作；
- 交接文件是跨会话唯一现场：新会话必须先读对应 `.zcode/tasks/<slug>.md` 再动手（同《长任务交接规则》第五节）。

## 三、边界与禁止

- 推送远程（push）**必须**经「提交代码zcode」的选择环节由用户确认，任何情况下禁止静默推送；
- `.zcode/gameWork.md` 与 `.zcode/tasks/` 已被 .gitignore 忽略，保存/提交时不得 `git add` 它们（规则文件 `.zcode/rules/` 不忽略，随代码入库）；
- 下一阶段若需要用户决策（立项变更、花钱购买、外部依赖、剧情拍板），**先问再开工**——不满足"可自动续跑"条件，不算流程中断；
- 自动保存的 commit 信息必须按技能规范如实总结本次改动，禁止把用户自建的未跟踪文档混入总结（除非它属于本需求产物）。
