# 长任务交接规则（断点续跑）

长任务在当前会话窗口跑不下（上下文即将耗尽）时，**必须**自动生成交接 MD 文件，记录已完成与未完成内容，供用户开新对话窗口继续任务，无需用户提醒。

## 一、目的

用户会开新对话窗口续跑长任务。交接文件是跨会话的唯一现场：新会话对任务一无所知，全靠它恢复上下文。

## 二、触发时机（强制）

- 长任务**开工时即创建**交接文件（不等快满才写），随进度**每完成一个里程碑/阶段立即更新**——防止上下文突然被压缩截断丢失现场
- 出现以下信号时**立即**做一次完整更新并告知用户可开新窗口：收到上下文压缩/总结提示、剩余窗口明显装不下剩余工作量、用户主动喊停
- 会话内能轻松完成的小任务不建文件（避免碎片化）

## 三、文件位置与命名

- 路径：`.zcode/tasks/<任务slug>.md`（slug=任务英文短名或拼音，kebab-case，如 `mountain-maze`、`shop-refactor`）
- **一个长任务一个文件**，续跑会话原地更新同一文件，禁止按日期新建副本
- 写「创建/最后更新」时间前先 `date` 取真实系统时间（同《需求变更自动记录规则》第三节纪律）
- 该目录已被 `.gitignore` 忽略（本地工作状态，禁止提交 git）

## 四、内容模板（必填字段）

```markdown
# <任务一句话标题>
状态：进行中 | ✅ 已完成（YYYY-MM-DD）
创建：YYYY-MM-DD　最后更新：YYYY-MM-DD HH:MM

## 任务目标
用户原话诉求 + 关键约束（不改什么/必须保什么）

## 已完成
- [x] 按里程碑分条；每条含：改了哪些文件、关键实现方式、验证结果（如 regress 118/0/0）

## 未完成（新会话从这里继续）
- [ ] 按优先级排好、可直接执行的下一步
- [ ] …

## 关键决策与踩坑
- 已定的方案/已否决的路线及原因/《开发必读-陷阱备忘》相关条目

## 现场
- 分支/未提交改动：…
- 验证命令：如 `python tools/regress_world.py`
- 相关文档：立项书/进度日志/陷阱备忘章节
```

## 五、新会话续跑（强制）

- 用户提到"继续XX任务"时，**必须先读** `.zcode/tasks/` 下对应交接文件（按 slug 或标题匹配），从「未完成」清单接着干
- 续跑的需求完成后，照常执行《需求变更自动记录规则》记录 `.zcode/gameWork.md`

## 六、完成与清理

- 任务全部完成：文件头状态改 `✅ 已完成（日期）`，正文保留供回看（由用户自行清理）
- 与 `docs/*-进度日志.md` 的分工：任务级断点续跑归本规则（`.zcode/tasks/`）；正式里程碑进度日志体系照旧不变

## 七、禁止事项

- **禁止**只记"做了什么"不记"怎么继续"——「未完成」清单必须可直接执行
- **禁止**把交接文件写到 `.zcode/tasks/` 之外散落
- **禁止**在上下文已明显不够时仍不建文件硬撑到被截断
