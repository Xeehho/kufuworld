# SCKR 素材组装语法考古（2026-09-07）

> 目的：解决"长安城处处合理但不合逻辑"的视觉问题（房子贴到一起/城门与城墙比例对接不上）。
> 方法：不做猜测——拆 RAR 原包、下载 itch.io 官方示例图、像素级实证（垛口周期/基线/模数），反推素材包的**组装语法**。
> 结论先行：**素材是按 RPG Maker MV/MZ 规格设计的整件 prop + 模数横带体系，我们的切片把"横带"截成了"碎片"、把"开间段"当成了"独立建筑"——语法丢了，不是素材不好，也不是生成器摆放算法不好。**

## 二、核心语法（像素实证反推）

### 语法1：城墙带 = 城门楼 + 城墙同模数横带（问题2根因）

源图 `jingcheng/tile-B-01.png` y=98~192 行，官方排版就是一条完整横带：

```
（_ana_wall_row.png 右侧可见：蓝顶城门楼-城墙-城门楼-城墙连续横带，垛口/墙身/墙脚全线连续）
```

实测数据：

| 部件 | 实框 | 高 | 底线 y | 备注 |
|------|------|----|--------|------|
| gate_tower_big（城门楼·大） | 473,98 → 568,192 | **94px** | 192 | 城 台顶从 y=126 起 |
| gate_tower_mid（城门楼·中） | 620,98 → 706,192 | **94px** | 192 | 同上 |
| 城墙带垛口顶 | — | — | — | **垛口凸起从 y=126 起** |
| wall_seg（现切片"城墙直段"） | 568,125 → 634,186 | **61px** | 186（差6px！） | 从横带上截的中段 |

**三条铁律**：
1. 城门楼与城墙**同高 94px、同底线**（y=192 货架线）；城台顶线 = 垛口顶线（y=126）。它们天生是一体的。
2. **垛口周期 ≈17.3px**（垛宽13~14px + 隙3~4px），**非 16、非 48 整除**——城墙段横向拼接必须按垛口**相位**对齐，任意宽度的段（现在的 wall_seg 66px = 3.8 个周期）重复铺必然错拍。
3. 现行"两行制"（垛口行70 + 砖身行106 = 32px 高 tile 墙）与 94px 城门楼比例 **1:3**，不在同一模数——这就是"城门和两侧城墙对接不上"的数学本质。

**正确拼法**：以城门楼为锚，城墙用**整带重切**——按垛口相位切 94px 高、含完整"垛口顶+墙身+墙脚"的横带段（段宽取垛口周期的整数倍），与城门楼同底线拼接；或直接切"城门楼±N垛口"的整条预制带。

### 语法2：民居 = 连排长屋，开间段不是房子（问题1根因）

源图 `jiangnan/tile-B-04.png`（_ana_house_rows.png）三行结构：

- 第1行：**连排长屋整栋** = 连续瓦顶横带（横贯全行）+ 开间序列（窗间墙 house_win_a / 门间墙 house_door_a 密排）+ 梯子/盆栽点缀。
- 第2行：瓦顶横带 + 窗开间 + **马头墙**（高出屋面的装饰山墙）+ 木门面/开敞店排（house_shop_open = 2开间店，190×96）。
- 第3行：**独立小宅**（三角瓦顶山墙正面朝玩家）+ 石基院墙 + 门楼（compound_gate）。

**三条铁律**：
1. `house_win_a`/`house_door_a`/`house_win_small` 是**长屋的开间段**（一段窗墙/一段门墙），**不是独立建筑**。单栋长屋 = 瓦顶横带 + N 个开间段 + 两端山墙封口。
2. **瓦顶横带是独立部件，manifest 里没有切**（216 条里零屋顶件）——开间墙片直接立在地上，"房子没有屋顶"就是这么来的。
3. 这套包是**南立面视角**（所有建筑正面朝玩家），**不存在"侧面/背面"立面**——用户看到的"有的正面有的侧面被贴到一起"，实际是**不同排/不同族的开间段被当独立房子散贴**（changan_generator.gd `HOUSE_PROPS` 随机池混了 4 种开间段+马头墙+影壁），且各行段高不一（83~96px），混排必然参差。

**正确拼法**：新增切片"瓦顶横带"+"山墙端头"；生成器新增"排屋组装器"：`整栋 = 顶带 + [开间序列] + 端山墙`，开间段从同一行取（不跨行混拼），底边统一地面线。

### 语法3：货架纪律（通用）

- 190 个 prop 中 71%~87% 的框边落在 48px 格线上（偏差≤4px），底边对齐率最高（87%）——**底边=地面线**是全包通用约定，prop 摆放必须脚底锚定。
- demo1 货架图同族建筑同行排列、同底线——同族才能互拼，**跨族拼接（如把宫殿族台基配民居族墙）无官方依据**。
- A4-Walls 表是**墙面材质库**（48px 面片，供 RM autotile），不是城墙结构件——城墙的结构（垛口/墙身/墙脚）只在 B01 的横带里。

### 语法4：宫墙带 = 宫门嵌墙（2026-09-07 补考古）

源图 `jingcheng/tile-B-03.png` y=128~192 行（_ana_palace_wall.png）：

| 部件 | 实测 | 说明 |
|------|------|------|
| 宫墙（palace_gate_gold 左右段） | **总高 50px**（y142→191） | 三段式：金瓦顶带（y142 起）+ 红墙身 + 灰石墙脚（y176 起透视内收 7px→5px） |
| 宫门 palace_gate_gold | 96px 高（y96→192） | 与宫墙**同底线 y≈192**，门楼嵌在墙带中，左右墙带向两侧延伸 |
| 太极殿 hall_taiji | 96px 高（144×96） | **独立大件不嵌墙**：重檐金顶+白石台基+丹陛台阶，属院内陆置（宫门之内） |

**新根因 R5**：现行 manifest 的 `wall_palace` composite_tile strips 三段合计仅 **24px 高**，与 96px 宫门比例 **1:4**（比城墙 1:3 更严重），且丢失墙脚透视内收与完整瓦顶带——宫墙与宫门对接不上与城墙是**同一类病**。

## 二b、样板间推断方法论（三层证据，不是猜）

样板间里"城墙/皇宫怎么拼"的每一处决定，都必须能指到以下三层证据之一：

1. **官方排版证据（最硬）**：货架图/展示图里作者怎么摆，我们就怎么拼。官方图里城门楼两侧直接连着城墙带（_ana_wall_row.png）、宫门两侧连着宫墙带（_ana_palace_wall.png）、长屋=顶带+开间序列（_ana_house_rows.png）——"同带摆放"就是官方认定的可互拼关系。样板间内容也只选官方图出现过的组合，不自由发挥。
2. **像素实测证据**：把排版量成数字，数字直接变成拼装规则和探针断言——底线 y=192 全族统一；城台顶=垛口顶（y=126）；垛口周期 17.3px（相位对齐）；宫墙 50px/宫门 96px 同底线；墙脚内收量 7px。凡是能量出来的都写成断言，不靠目测。
3. **RM 规格语法（兜底）**：48px 货架模数、A4 三段式、底边=地面线——用于解释"为什么"，以及官方图没覆盖的角落情况（如墙线拐角收头）时的推理依据。

**推断流程（以城墙为例）**：官方图读出"门楼±墙带一体" → 实测得"段高94/底线192/相位17.3px" → 推出规则"直段按垛口相位整周期重切、与门楼同底线拼接" → Godot 摆样板间 → 同点位截图与官方图并排 → vision 对照评审 → 通过才固化进生成器+探针。

**诚实边界**：官方没给场景级示例图，墙线**拐角/端头收头**、宫墙与太极殿院落的纵深关系这类细节无官方背书，属少数需要人工定夺的"设计决策"——样板间阶段单独标注出来请用户过目，这也是想找作者要示例工程的原因。

## 三、根因链总结

| # | 根因 | 表现 | 影响面 |
|---|------|------|--------|
| R1 | 开间段被当独立建筑散贴（无顶带/无连排/跨行混拼） | "几个房子贴到一起、朝向乱" | 全部坊市街区 |
| R2 | 城墙 32px tile 两行制 vs 城门楼 94px prop，模数断裂 | "城门与城墙比例对接不上" | 四大门/宫墙/市墙 |
| R3 | wall_seg 66px 非垛口周期整数倍 + 底线差 6px | 墙段重复错拍、与门楼不齐 | 墙线全程 |
| R4 | manifest 只有"有什么"没有"怎么拼"——组装语法层缺失 | 生成器只能按名随机贴 | 系统性 |

## 四、修复路线（建议顺序，样板间先行）

1. **重切**（改 `tools/import_sckr_changan.py` 清单）：
   - 城墙整带段（94px 高、垛口相位对齐、含顶/身/脚，建议直接切"门楼±2垛口"预制带 + 可延长的直带段）
   - 瓦顶横带（江南 B04 第1/2行顶部）、山墙端头、马头墙完整件
   - 每条新切片登记垛口相位/顶带跨度等语法参数进 manifest
2. **规格卡**：每类建筑一张卡（部件清单/拼接顺序/底线/相位），写进 `docs/长安城生成范式v3-工程化解析.md` 或独立文档
3. **样板间**：一段城墙+一个城门+一栋三开间连排屋，人工确认 → vision 对照 `_ana_wall_row.png`/`_ana_house_rows.png` 评审 → 再全城铺开
4. **探针断言**：城墙线底边同 y、垛口相位对齐、连排屋顶带连续无缝、开间不跨行——程序化断言进 E2E
