# 江湖志·武侠世界重构规划（World Rebuild Plan v2）

> 起草：2026-08-31。目标：**先立世界，后立玩法**——一次性把地形气候、城池规划、河流桥梁、可行域、NPC 驻留做对，任务系统整体冻结，之后逐阶段回归再开启。
> 本文档是实施总纲。动工前必读 `docs/开发必读-陷阱备忘.md`（42 条坑）与 `docs/验收标准.md`；每阶段动工前重读本阶段章节。

---

## 0. 背景与痛点（为什么重构）

2026-08-31 四轮验收暴露的系统性问题，全部源于"**多系统在同一份过程式代码里互相覆写**"：

| # | 痛点 | 根因 |
|---|------|------|
| 1 | 群系违和（雪地长草、城镇落沙漠） | 群系只决定装饰密度，铺设点各自硬编码；后补丁式加 `BIOME_PALETTES` |
| 2 | 城镇选址随机、形状随机 | `_generate_towns` 纯随机撒点+模板拼装，无规划语义 |
| 3 | 城市曾把穿城河整体铺死 | 城市/城镇/河流互相覆写 `override_cells`，无"河道保留"语义（后补 `_get_ground_tile` 避水） |
| 4 | 桥梁是平板木牌，风格丑 | tile 17 单瓦片贴图，无造型语义 |
| 5 | 碰撞体分散（岩石/树/建筑各自为政） | 碰撞来源有三处：TileSet 物理层、footprint 39、道具 StaticBody，无统一可行域策略 |
| 6 | NPC 生成混乱、到处游走 | 自动日程随机分配，与建筑/职业无绑定 |
| 7 | 改 A 坏 B（桥梁好了城池坏了） | 无特性开关、无逐阶段回归断言，验收靠截图走查 |

**结论**：世界生成需要从"过程式堆叠"转向"**规划式分层**"——先画蓝图（数据），再按层施工（生成器），每层只读下层、不写兄弟层。

## 1. 总体架构原则（贯穿所有阶段）

1. **单一事实源（SSOT）**
   - 地表最终状态只有一个查询口：`WorldGenerator.get_tile_id(x, y)`（override 表仍保留，但**只有规划层可写**）。
   - 碰撞唯一物理来源：`tileset_generator.collision_tile_ids` + 建筑 footprint(39)。禁止第三处再出现 StaticBody（现有 props 除外）。
   - NPC 落位唯一来源：`city_info["buildings"]` / `town_info["buildings"]` 的 `door_px`，禁止 NPC 生成器自己算坐标。
2. **数据驱动**：门派/城池/村镇/桥/NPC 岗位全部收敛为**常量数据表**（GDScript const 字典起步，够用），生成器只做"按表施工"。
3. **特性开关**：新增 `scripts/world_features.gd`（static const），每个新系统一个 bool。旧路径保留在开关后，可单独回滚：
   ```gdscript
   const FLAG := {
       "tang_city": false,        # Phase W2
       "sect_territories": false, # Phase W3
       "town_v2": false,          # Phase W4
       "npc_static": false,       # Phase W4
       "quests_disabled": true,   # Phase W4 起冻结任务
       "bridge_prop": false,      # Phase W5
       "walkability_policy": false, # Phase W6
   }
   ```
4. **生成顺序固化**（先低后高，兄弟层互不可见）：
   ```
   气候/群系 → 河流水文 → 可行域骨架(山体/荒野) → 城池 → 村镇 → 门派领地 → 桥梁/官道接驳 → NPC/怪物落位
   ```
   每层只允许"检测兄弟层"（如避水、避城），不允许"改写兄弟层"。
5. **每阶段结束必须回归**：`tools/regress_world.py`（见 §10）跑全量历史断言，任一红灯不得进入下一阶段。

## 2. 世界地图模型 v2（气候分区 + 门派领地）

### 2.1 气候驱动的群系分布（自然规律）

废弃"随机撒 14 个 Voronoi 种子"的做法，改为**气候场决定群系**（`world_generator.gd` 重写 `_setup_biomes`）：

- **温度场** `temp(x,y)`：纬度基线（北冷南暖，y 越大越暖）+ 海拔修正（`get_height` 越高越冷）+ 噪声扰动。
  - `temp < 0.25` → 雪；`< 0.45` → 山地/针叶；`< 0.7` → 平原/森林；`≥ 0.7` 且湿度过低 → 沙漠。
- **湿度场** `hum(x,y)`：现有 `get_humidity` 保留，加"临水加湿"：距河/湖 ≤12 格湿度 +0.2（河谷竹林、湖畔沃野的自然来源）。
- **群系判定的唯一入口**：`_climate_biome(x, y) -> String`，替换 `_biome_kind` 的 Voronoi 逻辑；`_palette_at`/`_ground_of`/`_biome_nearest_two` 全部保留（调色板机制已验证好用）。
- **确定性**：种子仍由 `WORLD_SEED` 派生，同一版本地图完全一致；`WORLD_SEED` 写入常量并登记版本号（改布局必须升版本+重跑回归）。

自然规律硬规则（生成时校验，违反即断言失败）：
- 雪群系不出现任何绿色系瓦片（已达成，纳入回归）；
- 河流必须"源高山、终湖泊/出海口"：河流生成改为从 2-3 个高山源点向下坡度游走，终点接入湖/边界深水，不再正弦横穿；
- 湖泊 ≥1 且不与城/镇/领地重叠；
- 树木密度 = f(湿度)：沙漠 0、雪原仅雪松、竹林必须湿度>0.6 区域。

### 2.2 门派领地（教派划界 + 建筑风格）

新数据表 `SECT_TERRITORIES`（放 `scripts/world_data.gd`，新文件）：

| 门派 | 驻地气候位 | 领地半径 | 样式基调 | 与 ClanSimulator 关系 |
|------|-----------|---------|---------|----------------------|
| 青峰剑宗 | 温带山地（雪山南麓） | 28 | 青瓦白墙·蓝旗·剑架演武场 | `resources/clans` 剑宗 |
| 铁砂帮 | 沙漠东缘绿洲 | 24 | 夯土石堡·土黄·红旗 | 刀盟 |
| 古刹禅宗 | 竹林北缘 | 26 | 金脊琉璃·黄墙·钟楼 | 禅宗 |
| 药王谷 | 湖畔竹林 | 24 | 竹楼青瓦·药圃篱笆 | 药王谷 |
| 幽冥教 | 雪原腹地黑岩区 | 28 | 黑瓦朱柱·黑旗·白骨幡 | 幽冥教 |

领地生成规则（`_generate_sect_territories`，新函数）：
1. 选址：在对应气候区内找 20×20 全可行（非水非崖）区块；领地间距离 ≥45，距青石城 ≥40，距村镇 ≥20。
2. 划界：领地边界每 6 格放**界碑**（新 tile，含浅碰撞），主轴上放**山门牌坊**（新 prop，跨路 3 格）。
3. 建筑组：山门 → 主殿（大建筑，accent=门派主色）→ 演武场/药圃/钟楼（功能差异化）→ 弟子舍 ×2 → 后山禁地（不可行区，崖+雾装饰）。
4. 样式系统：把 `_compose_big_building(..., accent)` 的单色 accent 升级为 `STYLE` 字典：
   `{roof: Color, wall: Color, ridge_gold: bool, banner: Color, props: [...]}`
   每门派一个 STYLE；城镇民用建筑用"民居 STYLE"。`_compose_big_building` 只认 STYLE，不再散传参数。
5. 门派 NPC（弟子/长老）挂领地建筑锚点（与 §7 NPC 驻留制同一套机制）。

## 3. 青石城 v2：唐代城池制（本阶段最重）

参考唐代长安/洛阳形制，落地为 61×61 瓦（`CITY_HALF` 22→30）。**核心原则：市坊分离、棋盘路网、中轴居北、四门官道。**

### 3.1 城内布局（`_generate_city` 按蓝图重写）

```
                     ▲ 北门·拱辰门
        ┌─────[官署坊]─────┬────[寺观坊]────┐
        │  府衙+捕头厅      │   古刹(分寺)    │
        │                  │                │
  西门  │   居住坊·西       │   居住坊·东     │  东门
·西成门 │  (民居×8~10)     │  (民居×8~10)   │ ·东作门
        │                  │                │
        ├─────[西市]───────┴────[东市]──────┤
        │  行肆:铁/药/布     │   行肆:杂/酒/食  │
        └──────────────────┴────────────────┘
                     ▼ 南门·明德门
```

- **路网**：中央十字大街（南北"朱雀大街"+东西大街）**宽 4 格**，直通四门；平行次街每 10~12 格一条，**宽 2 格**；坊内巷道 1 格。所有路=调色板 path（保留现有群系化）。
- **四门**：每边正中 3 格豁口（现有机制保留），门内大街命名：南门内为主轴。四门外各接一条**官道**（宽 2 格，见 §5 桥梁接驳）。
- **里坊**：四大居住坊，每坊约 20×18，**坊墙 1 格 + 坊门 2 格**（新 tile 41 坊墙，复用城砖纹理淡色版；坊门=路）。坊内民居 8~10 座，**房间距 ≥2 格**（防火巷），民居 STYLE 统一。
- **东西两市**：商业集中两市（16×14），行肆排列——铁匠铺/药铺/布庄在西市，酒楼/杂货/食肆在东市；市中心水井+市棚。店铺不再散布坊内（唐制"市"外不临街开店）。
- **官署坊**：府衙+捕头厅占北门内西侧一坊（唐制官署居北）；**寺观坊**：古刹分寺占东北一坊（金脊 STYLE）。
- **职业分区**即行肆：同业相邻，NPC 岗位按铺位生成（§7）。

### 3.2 与现有系统的关系

- `city_info` 结构升级：`{center_px, gates:{n,s,e,w}, wards:[{rect,name}], markets:[...], buildings:{key:{anchor,fp,door_px,job}}}`。**NPC/任务/寻路标注只准读它**。
- 河道保留语义沿用第三轮成果（地坪避水、水门、街桥）；城内河道若穿过坊，坊墙在河道处改**水关**（同水门样式）。
- 城墙：现有 tile 40 + 8px 大城砖纹理保留；四门加**城门楼** prop（新，跨门 3 格，两层楼子）。

## 4. 村镇模板 v2（乡野形制）

村镇不做里坊（唐制村镇本就无坊墙），但要有"**一圈一团一水**"的聚落逻辑：

- 选址硬规则：距城 ≥34、距门派领地 ≥20、村镇间 ≥24、**河畔优先**（距水 6~12 格，绝不压水——第三轮已实现避水，保留）、气候限平原/竹林/山地南麓（雪/漠/湖仍排除）。
- 布局模板（`TOWN_TEMPLATES` 重做，3 选 1）：
  - **农耕村**：环状农带（靠水一侧）+ 十字土路 + 祠堂/场院 + 民居 4~6；
  - **市镇**：一条主街（宽 2）两侧行肆 + 民居 5~7 + 骡马店；
  - **渡口村**：临河一侧渡亭 + 渡口官道直通桥头（§5）+ 民居 4~5。
- 村内职业最小集：村正、农人×2、铁匠或货郎、渡夫（渡口村）。全部驻留制（§7）。

## 5. 河流水文与桥梁 v2

### 5.1 水文自然规律（重写 `_generate_rivers`）

- **源—流—汇**：河源固定 2~3 个（雪山/高山群系内），沿 `get_height` 下坡方向游走（带噪声摆动），汇入湖泊或边界深水；支流允许在平原汇入干流。
- 河宽干流 4、支流 2~3；河岸沙带 1 格（现有）。
- **永不改写**：河流层生成后，只有 §5.2 的桥与水关可以在河上"落东西"，其余层一律避水（已有逐格避水，保留并纳入回归）。

### 5.2 石拱桥 prop（替换平板木桥观感）

- 新 prop `BridgeProp`（`texture_generator` 新增 `_bridge_stone(W)`）：
  - 灰白条石桥面 + 两侧**石栏板+望柱**（每 8px 一柱）+ 桥端石阶过渡 + 桥下拱腹阴影弧；
  - 宽度=所接路宽+2，长度=河宽+4（数据按河宽取档：窄桥 5 格/宽桥 7 格）；
  - 逻辑上仍占 tile 17（可通行、无碰撞），视觉由 prop 承担——**桥的可通行语义与外观彻底分离**。
- 放置规则（`_place_bridges`，新函数，替换"每隔 15 格无脑架桥"）：
  1. 四门官道与河交叉处**必有桥**；
  2. 城镇主街朝河一侧端点若隔河有目标（官道/领地山门）→ 渡口村配渡亭否则配桥；
  3. `_ensure_connectivity` 的 pocket 修补仍可用旧逻辑（桥 17），但刷完后跑桥位审计（§10）。
- 城内水关样式与桥统一（水门=小型石拱）。

## 6. 可行域与碰撞治理（把"可行"变成一级概念）

新增 `WalkabilityPolicy`（`world_data.gd` 内的规则表 + `world_generator` 执行）：

- **分区**：`SETTLEMENT`（城/镇/领地建筑区）、`ROAD`（大街/官道/巷）、`FARM`、`WILD`、`HOLY_GROUND`（后山禁地等故意不可行区）。
- 生成期规则：
  1. `SETTLEMENT/ROAD/FARM` 内**禁止**放置任何含碰撞的装饰（岩 14、崖 3/7、树 prop 的碰撞变体）；
  2. `WILD` 内碰撞物**聚簇**：岩石只贴山系 3 格内成带状出露（2~5 格连片），不再全图撒 singles；
  3. 任何两点间的野外通行走廊宽度 ≥2 格——由 `_ensure_connectivity` 升级为**走廊宽度感知 BFS**（把 2×2 可通行当作连通条件），修补优先桥 17，其次沙 6。
  4. **山地通过性规划（W9，2026-09-03 用户反馈"山地全是死路"后细化）**：崖壁质量场的负空间不作为路网——纵横山口垭口网格（间距 18±5，穿崖必开 3 宽沙口，任何谷地距最近山口≤约 11 格）+ 绝径归崖（山/雪 WILD 死路子树叶子剥离填崖，度≤1 迭代至不动点）；两者避城圈/镇圈/领地/官道/净空，详见进度日志 §二·L。
- 运行期唯一查询：`world_generator.is_walkable(tx, ty)`（= 该格无碰撞瓦片且无 footprint）——怪物 AI、NPC、探针断言全部只调它，禁止各自再猜。
- **禁地**：后山禁地/城墙外深水等故意不可行区用界面语言表达（崖+雾+界碑），并写入 `world_data` 供小地图配色。

## 7. NPC 驻留制 + 任务冻结（先立世界，后立玩法）

### 7.1 任务整体冻结（可回滚）

- `GameManager` 增加 `feature_flags`（读 `world_features.FLAG`）；`quests_disabled=true` 时：
  - `main_story._start_when_ready` 直接 return（主线不自动开）；
  - `QuestSystem` 不发布任何可接取任务（日志面板空态文案："江湖暂无委托"）；
  - `EncounterSystem` 保留奇遇弹窗但关闭任务型奇遇（纯风味奇遇保留，供世界"活"感）；
  - `mob_spawner.spawn_story_camp` 永不被调用。
- **删除为 0**：全部是开关，Phase W8"任务重启"时逐项打开并回归。

### 7.2 NPC = 岗位 + 驻留

- 数据表 `NPC_JOBS`（`world_data.gd`）：
  `{job: 铁匠, building: smithy, title: 铁匠·王大锤, look: merchant, spawn_offset: 门口(2,1), schedule: [[idle_hold, 全天]]}`
- `npc_spawner` 重写落位逻辑：
  1. 城内：遍历 `city_info["buildings"]`，按 `job` 字段生成对应 NPC，位置= `door_px + spawn_offset`（**只读 door_px，禁止自算坐标**）；
  2. 村镇：`town_info["buildings"]` 同理（村正@祠堂、铁匠@铁匠铺、渡夫@渡亭）；
  3. 门派：领地建筑锚点（弟子@演武场、长老@主殿）。
- **行为**：`npc_static=true` 时全部 `idle_hold`（原 legs 机制保留代码，开关切回即恢复巡游，供 Phase W8 复用）；对话/查看面板/商店照常可用。
- 数量：城内 12~14（府衙 3、四门守卫 4、两市行肆 5~6）、每村 4~5、每领地 3~4。总量 ≤45，性能可控。

### 7.3 怪物（沿用第三/四轮成果，纳入回归）

- 营地避城收敛解析、故事营地避让、mob 实体禁入聚落——全部保留为常驻规则；怪物只在 `WILD` 分区刷。

## 8. 纹理与素材规范（防止"掺材质"复发）

- **噪声规范**：程序化贴图一律使用**异或混合哈希** `((x*73856093)^(y*19349663))%997`；**禁止** `x*a+y*b` 形式取模（线性=斜条纹，8-31 已踩坑）。
- 新增贴图清单（全部走 `Main._ensure_textures` 自动补生成纪律：改=删 PNG→跑游戏）：
  界碑(16)、山门牌坊(prop)、城门楼(prop)、坊墙(41)、坊门、石拱桥(prop，三档宽)、渡亭(prop)、旗杆/幡(prop，颜色由 STYLE)、禁地雾石(装饰)。
- 建筑一律 `_compose_big_building(STYLE)`；16px 小屋沿用现有中式 `_mini_house`（补：其 plaster 仍取自素材包裁切，Phase W6 顺手换纯色+点噪，消除最后的材质杂味）。
- 素材包边界：现有 Pixel Crawler 包只用于**树/角色/怪/地形基面**；一切"人造物"（建筑/桥/墙/坊）保持程序化中式，不再从包里裁（杜绝材质掺混）。

## 10. 验收与回归体系（治"改 A 坏 B"的根）

### 10.1 自动化回归 `tools/regress_world.py`（W0 建立，逐阶段增补断言）

沿用 `run_biome_shots.py` 的临时 autoload 模式（跑游戏→采样→还原 project.godot），断言清单：

| 断言组 | 内容（全部为硬断言，输出 PASS/FAIL+数据） |
|--------|------------------------------------------|
| biome | 雪/漠/湖群系 49×49 直方图（禁瓦片集合）；气候连续性（无飞地） |
| water | 非桥覆水计数=0；河源在山、河口在湖/边界；∀河 8 格内无城心/镇心 |
| city | 四门可达市与各坊（BFS）；房间距≥2；footprint 无重叠；水关在位 |
| bridge | ∀(官道×河)交叉有桥；桥宽=路宽；桥下是水 |
| sect | 5 领地在位、间距、主色占比、界碑环闭合 |
| npc | ∀NPC 距所属 door_px ≤3 格；任务发布数=0（冻结期） |
| mob | 营地 in_settlement=false；怪实体全在 WILD |
| walk | SETTLEMENT/ROAD 无碰撞物；走廊连通 |

### 10.2 截图走查

探针机位扩充为 **14 机位**：现有 5（城广场/府衙/村镇/雪×2）+ 城四门 4 + 桥近景 3（窄/宽/水关）+ 领地山门 2。每阶段验收必须贴当阶段机位图于 `docs/shots/`。

### 10.3 回归矩阵（防"改 A 坏 B"的制度保证）

每次改动后，**无论改动属于哪个系统**，回归脚本跑的是**全部历史断言组**（不是只测本系统）：
- 改桥 → biome/water/city/npc 断言照样跑（第三轮"桥好了城坏了"的直接教训）；
- 断言失败的处理纪律：先修因，禁止改断言凑绿；确属规则变更需在本文档登记并升 `WORLD_RULES_VERSION`。

### 10.4 手动冒烟单（W7 终验）

出生点 → 沿官道进城（过桥）→ 四门各走一遍 → 东西两市逛铺 → 逐坊走查房间距 → 出北门官道赴剑宗（过山门/界碑）→ 五领地各访一遍 → 雪原/沙漠/竹林各站 1 分钟（观感+怪物行为）→ 清一座怪营 → 存活 10 分钟观察 respawn。

## 11. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 城池扩到 61×61 导致 NPC/怪物/性能压力 | NPC 总量 ≤45；chunk 加载半径不变；城仍走 `_load_poi_chunks` 强制加载 |
| 领地与村镇/河在边缘打架 | 选址硬距离表 + 生成顺序（领地在村镇后，只准避让不准改写村镇） |
| 唐制坊墙把玩家困住 | 坊门≥2 格/坊，连通断言覆盖每坊 |
| 新贴图批量引入管线事故 | 严守"删 PNG→跑游戏自动重生成"；禁止 runtime generate_all；新 PNG 一定走 `TextureGen.load_png_texture` |
| 任务冻结误伤对话/商店 | 冻结只关"发布"，交互层不动；W4 验收含对话冒烟 |
| 一次性重构失控 | FLAG 隔离 + 串行阶段 + 全量回归三重保险；任何阶段可独立回滚（FLAG 关闭即回旧路径） |
