# 画面改造方案 —— 中国风武侠版星露谷视觉对齐

> 目标：让运行画面贴近 `docs/材质包图片`（Pixel Crawler 素材包样图）与 `docs/learn`（星露谷截图）的观感。
> 本文档是改造总纲，按 Phase 分阶段执行，每个 Phase 独立可验收，完成后停下等确认再进入下一阶段。

---

## 一、差距根因分析（为什么现在不像）

对比三组参考图与 `docs/shots/w8_*.png` 运行截图，按视觉冲击力排序：

| # | 差距 | 星露谷/素材包样图 | 当前项目 | 根因 |
|---|------|------------------|---------|------|
| 1 | 地表质感 | 草地每格有草丛/色斑/明暗变化，暖黄绿色调 | 近乎纯色平铺，大面积"色块感" | 全世界草地只用**一张** `Floors_Tiles(2,10)` 单格填充（texture_generator.gd L81），无变体无杂色 |
| 2 | 投影 | 树/建筑/角色脚下均有椭圆软阴影 | 全场景无投影，物体像贴纸浮在地面 | 从未实现过阴影层 |
| 3 | 装饰密度 | 地表散布石子/蘑菇/花/草丛，几乎无空格 | 大片空地，装饰仅零星几朵花 | `_biome_decor_tile`（world_generator.gd L2355）阈值过严，且装饰种类少 |
| 4 | 地形过渡 | 草↔沙↔水之间有融合过渡瓦片 | 纯绿与纯米色硬拼接，边界生硬 | 未使用素材包自带的 blob 过渡瓦片 |
| 5 | 建筑体量 | 4x4~6x6 格，瓦楞屋顶/烟囱/窗框/檐下阴影 | 2x2 格平涂小房子 | `_mini_house`/`_compose_big_building` 合成过于简化 |
| 6 | 水岸 | 水面波纹动画+岸线过渡+码头道具 | 单帧纯蓝硬边 | `water` 只裁了 `Water_tiles(6,7)` 一格，动画列未用 |

**核心结论：不是素材不行，而是素材只用了约 5%。** 素材包里真正值钱的资源（过渡瓦片、四季树、软阴影表、模块化墙体/青瓦屋顶、道具表）基本未启用。

## 三、分阶段改造方案

### Phase 1 地表质感（收益最大，改 3 个文件）

**目标**：消灭纯色平铺，草地达到星露谷式"每格都有细节"的暖色质感。

| 步骤 | 内容 | 涉及文件 |
|------|------|---------|
| P1.1 色板暖化 | `grass` 从 `Floors(2,10)` 换成更暖的填充格（或乘法调色：hue 向黄偏移、亮度微升）；`grass_dark/path/sand` 同步微调保持和谐 | texture_generator.gd L81-85 |
| P1.2 地面变体 | 每类地面裁 3~5 个变体（Floors_Tiles 同色系多格 + Vegetation 杂色草皮）；TileSet 用 `create_alternative_tile` 注册；world_generator 铺 Layer0 时用细节噪声抖动选变体（约 70% 主瓦片 / 30% 变体打散） | tileset_generator.gd、world_generator.gd、texture_generator.gd |
| P1.3 碎屑装饰层 | 新增小瓦片：草丛×3、小石子×2、落叶、野花×2（Vegetation.png 现成素材）；`_biome_decor_tile` 密度公式放宽（plains 约 30% 格出碎屑，forest 更密，desert/snow 用各自的碎屑组） | texture_generator.gd、tileset_generator.gd（decor_tiles 注册）、world_generator.gd L2355-2399 |

**验收标准**：
- 同机位截图对比：草地连续 3×3 以上同图案的区域消失
- 整体色调与 `docs/learn/image1.png` 的暖黄绿接近
- 平原行走视野内碎屑装饰密度 ≥ 星露谷截图的一半

**风险**：装饰密度提高会拉慢 chunk 首次生成时间（世界半径 200），需实测首开耗时；变体控制在每类 ≤5 个，避免 TileSet 构建变慢。

### Phase 2 光影（单项观感提升最大）

**目标**：所有立物"落地"，时段有温度。

| 步骤 | 内容 | 涉及文件 |
|------|------|---------|
| P2.1 角色阴影 | 程序化生成一张径向渐变椭圆阴影纹理（texture_generator 新函数，运行时共享单张纹理）；Player/NPC/Mob 的 CharacterBody2D 下挂 Sprite2D（z_index=0，贴脚底） | texture_generator.gd、player.gd、npc_character.gd、mob 脚本 |
| P2.2 建筑阴影 | building_prop 组节点（Sprite2D+StaticBody2D）脚底挂同款椭圆阴影（拉宽到建筑 footprint） | 建筑放置处（world_generator/_force_place_building_prop） |
| P2.3 树影烘焙 | 树是 Layer1 瓦片无法挂节点 → 直接把半透明椭圆**烘进树的 16x16 瓦片左下角**（texture_generator 树瓦片绘制处） | texture_generator.gd |
| P2.4 瓦片伪 AO | 地面瓦片（草/沙/路）下边缘叠 1px 半透明暗边，地面产生"厚度" | texture_generator.gd 各 `_tile_*` |
| P2.5 时段暖色 | weather_controller.gd 的 CanvasModulate 曲线：清晨/黄昏叠加暖橙调制 (1.0, 0.85, 0.7)，正午中性微暖 | weather_controller.gd |

**验收标准**：树/建筑/角色脚下均有椭圆软影；黄昏截图整体偏暖橙；地面瓦片边缘有暗线。

**风险**：阴影节点数量大（树很多），树影必须走烘焙方案而非节点；共享纹理避免重复加载。

### Phase 3 地形过渡与水体

**目标**：消灭生硬的地形拼接边，水面活起来。

| 步骤 | 内容 | 涉及文件 |
|------|------|---------|
| P3.1 草↔沙过渡 | Floors_Tiles 的 blob 过渡组注册为 Terrain Set（match corners_and_sides）；world_generator 地表铺设后二次扫描边界格，把纯色边界格替换为 8 向过渡瓦片（先做草↔沙、雪↔草两组） | tileset_generator.gd、world_generator.gd |
| P3.2 水岸过渡 | Water_tiles 岸线 blob（草↔水）同样处理；水瓦片换波纹填充格 | 同上 |
| P3.3 水面动画 | Water_tiles 的 4 列动画帧注册 TileSet animation（约 1.5fps 循环） | tileset_generator.gd |

**验收标准**：草/沙/水交界处均为融合过渡；水面有波纹循环动画；过渡不产生可达性变化（过渡瓦片无碰撞，与被替换地面一致）。

**风险**：blob 瓦片的朝向映射容易出错，需按 Godot 4 Terrain Set peering bits 仔细核对；`_ensure_connectivity` 与可达集不受影响（过渡瓦片不进 collision_tiles）。

### Phase 4 建筑与道具与季节树

**目标**：建筑达到参考图体量与细节，城内/农田布满生活道具，树木有四季。

| 步骤 | 内容 | 涉及文件 |
|------|------|---------|
| P4.1 建筑重做 | 用 `Buildings/Walls.png`（木框抹灰墙）+ `Roofs.png`（**青瓦顶**=中国风）合成 4x4~6x6 大建筑；重写 `_mini_house`/`_compose_big_building`；檐下挂阴影（P2.2 复用） | texture_generator.gd（建筑合成函数） |
| P4.2 城镇道具 | 红灯笼（程序化绘制，夜间自发光）、木桶/货箱（Props.png）、摊位加固幌子；城内主街/市场铺设 | texture_generator.gd、world_generator.gd 城池生成段 |
| P4.3 农田围栏 | Farm.png 的栅栏+稻草人+棚架，城镇农田区环绕铺设；作物苗期素材可替换 farm_system 现有 crop 贴图 | texture_generator.gd、farm_system.gd（可选） |
| P4.4 季节树 | Model_01 春绿/秋橙/枯木/雪覆变体按群系分配：forest=春绿+10% 秋橙，mountain=枯木混入，snow=雪覆树；竹子群系用 Vegetation 染色变体 | texture_generator.gd、world_generator.gd `_biome_decor_tile` |

**验收标准**：青石城主街有灯笼/桶箱/幌子；城镇农田有栅栏+稻草人；森林出现少量秋橙树、雪山出现雪覆树。

**风险**：建筑 footprint 变大需同步 override_cells(39) 碰撞占格与 `_try_place_town_building` 象限 bounds（half≥7 才容得下 temple 的规则要复核）；大建筑贴图尺寸上升需确认 `generate_big_buildings` 输出尺寸上限。

### Phase 5 中国风加分项（可选，全部完成后再议）

## 四、实施与验收流程

1. **每 Phase 一轮**：改完 → 启动游戏自动重建纹理（改动生成逻辑时需删 `sprites/tiles/*.png` 触发重生成）→ 用 godot MCP `editor_screenshot` 按 w7/w8 历史机位截图
2. **前后对比**：新旧截图并排与 `docs/learn` 参考图对照走查，逐项打勾，禁止整体印象式扫图
3. **回归探针**：跑既有截图探针脚本确认无布局回归；`_ensure_connectivity`/可达集/NPC 选址不受影响的项也要抽验
4. **记录**：每 Phase 完成写入 `.trae/gameWork.md`

## 五、全局风险与项目陷阱对照

| 风险 | 对应陷阱（docs/开发必读-陷阱备忘.md） | 对策 |
|------|--------------------------------------|------|
| 新裁切 PNG 运行时加载失败 | 运行时 PNG 无 import 数据，`load()` 失败 | 一律走 `TextureGen.load_png_texture()`；存在性判断用 `FileAccess.file_exists` |
| TileSet 碰撞/变体写入静默失败 | source 未 add 前设 TileData 无效 | 先 `add_source` 再写 TileData；alternative tile 同理 |
| 改生成逻辑不生效 | `generate_tiles()` 只在 PNG 缺失时生成 | 改动后删 `sprites/tiles/`（及 buildings/）对应 PNG 重生成 |
| 装饰密度↑ 拖慢首开 | chunk 生成耗时 | 实测首开时间；必要时 plains 密度降档 |
| 过渡瓦片影响通行 | collision_tiles 集合 | 过渡瓦片一律无碰撞、不改变可达集 |
| 大建筑 footprint 变化 | override_cells/39 与象限 bounds | 同步占格与 `_try_place_town_building` 校验 |
| 阴影节点过多 | 性能 | 树影烘焙进瓦片，仅角色/建筑用节点 |
| HUD 被色调调制影响 | CanvasModulate 作用域 | HUD 在 CanvasLayer 不受影响，现状架构已保证 |

## 六、建议执行顺序

```
Phase 1（地表） → Phase 2（光影） →  中期对比验收（截图 vs learn 参考图）
→ Phase 3（过渡+水） → Phase 4（建筑+道具+季节树） →  终期走查
→ Phase 5（加分项，视效果决定）
```

Phase 1+2 完成后预期即可达到参考图七八成观感，届时再决定 3/4/5 的投入深度。
