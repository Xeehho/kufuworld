## 一、目标与范围

用样板区验证过的**地块式布局**（三级路网 / plot 记录制 / Prefab 库 / 密度装点）替换三类聚落生成：

| 对象 | 现状 | 目标 |
|------|------|------|
| 6~9 镇（`_generate_towns`） | 十字土路+象限撒屋（`_place_town_building` 四象限随机试锚），无地块概念，密度低 | 地块式布局：主巷/支巷/门前径三级路网，每栋隶属围合地块，密度按样板区量化标准 |
| 青石城坊内（`_generate_city`） | 里坊骨架已有（4 坊墙+坊内巷+两市），坊内建筑裸摆、装点稀疏 | 坊内地块化：院墙+檐下道具+装点密度增强，27 建筑锚点 key 不变 |
| 门派殿堂区（`_generate_sect_territories`） | 25×25 清场裸摆 3 栋（主殿+弟子舍×2）+演武场石板 | 殿堂区庭院化：院墙/山门/回廊/石灯笼装点，主殿轴对称布局 |

**非目标**（本期红线）：
- 不动河流走向、官道走向、群系分布、POI 类型与选址
- 不改 NPC 行为逻辑（NPC 只随登记表锚点自动跟随）
- 不改城/门派选址算法（只改选中后的"怎么建"）

## 三、技术方案

### 3.1 模块泛化：town_demo_kit → town_layout_kit

新建 `scripts/town_layout_kit.gd`（RefCounted 工具类，不挂节点），样板区能力下放：

```
town_layout_kit.gd（静态/实例工具）
├─ apply_template(wg, spec) -> town_info-like   # 总入口
│   spec = { center, half, template, plots[], jobs, ferry_axis... }
├─ _stamp_plots(spec)      # 地块表驱动：外部传入 plot 表（kind/bounds/door/job）
├─ _lay_roads(spec)        # 三级路网参数化（主巷宽/支巷走向按模板）
├─ place_building(kind, anchor, fp, job, register_39=true)  # 39 占格 + Prefab 精灵 + StaticBody
├─ _fence_ring / _build_yard / _build_farm / _scatter_props   # 原样迁移
└─ _report_density(region) # 密度量化（回归探针消费）
```

- `town_demo_kit.gd` 保留不动（样板区是已验收产物，作为参照样本存续；待 M2 完成后评估是否让样板区改走 kit——**本期不做**，避免样板区回归波动）
- 镇建筑落位沿用现行 `_place_building_prop`（39 占格+Sprite+StaticBody 五节点形态），仅把精灵来源换为 Prefab 合成器、落位算法换为地块表驱动
- Prefab 合成器（`_compose_demo_house`/`texture_generator.generate_demo_buildings`）泛化风格参数：按镇模板/门派 style 出主色（青峰青瓦/幽冥暗瓦等）

### 3.2 镇改造（M1/M2）

- **选址算法零改动**（24 镇距/46 城距/可达/无水/无崖/ferry 岸位三重验证全部保留——`sect_count_5` 依赖的否决分布才不被扰动）
- **语义槽位保留**：三模板的建筑清单与 job（村正/农人/铁匠/货郎/客栈）不变，只是"怎么摆"换成地块式：
  - farm：祠堂+农舍×2+店+民居 4~6 → 地块围合，主巷串南北，农带保留 tile 16（`_dress_farm_bands` 全局装点链不动，风险最低）
  - market：+镇心广场（石板升级为样板区水井广场规格）+坊市摊位意象
  - ferry：渡亭岸位/`ferry_axis`/石拱桥规则全部保留，宅区地块化
- 布局总图（farm 模板示例，half=8 → 可扩至 half=10~11）：

```
┌─────────────────────┐
│ 农带 L 形(2宽 tile16) │
│  ┌────┐ ┌────┐      │
│  │祠堂│主巷│民居│      │
│  └─┬──┘ ║ └─┬──┘     │
│  ══支巷═╝   ║        │
│  ┌────┐ ┌────┐      │
│  │农舍│主巷│店铺│      │
│  └────┘ └─┬──┘      │
│  农带      支巷→村口   │
└─────────────────────┘
门径/巷/密度：door 4 格内有巷 100%、装饰 ≥25%、footprint ≥22%（样板区标准）
```

### 3.3 青石城坊内（M3）

- 里坊骨架/四门/主街/广场/市巷**全不动**（城是 `_force_place` 落位，重排自由度大）
- 坊内增强：坊内巷两侧装点（灯笼/花簇/桶箱 prop 组）、house/hut 建筑加院墙+檐下道具、市摊周边货台化
- **27 建筑 key 与 anchor 语义不变**（city_npc_configs 11 人 ref 键硬依赖）；若个别锚点需微调，同步改 npc_spawner `city_npc_configs`
- 坊内密度目标：装饰 ≥20%（城内略低于镇，预算控制）

### 3.4 门派殿堂区（M4）

- 主殿轴对称庭院化：山门（南）→ 前坪石板 → 主殿 + 两侧配殿/回廊 prop + 石灯笼
- `npc_anchors{hall,arena}` 语义不变（hall=主殿门 px，arena=演武场中心 px）；新增建筑走 npc_anchors 之外的位置
- 界碑环/后山崖带/选址零改动

### 3.5 断言升级 v4（M0 先行）

| 动作 | 断言 | 说明 |
|------|------|------|
| 废除硬编码 | `sect_dist_city`×5 / `gate_*` / `river_not_through_city` / `city_interior_dry` 的 (75,0)/city_half=30 | 改读 `city_info`（探针注入 wg 已有引用） |
| 参数化 | `settlement_road_no_collide` 镇采样圆 13 → `town_info.half+4` | 镇 half 扩大后仍全覆盖 |
| 保留重测 | `sect_count_5` / `sect_gap_*`×10 / 每镇 door BFS / `_chief` / `_shrine` / `_ferry_pavilion` / `footprint_no_water` / `npc_anchor_dist_le3` | 语义不变，M1~M4 逐阶段复跑 |
| 新增关系断言 | `town_{i}_door_on_lane`（每 door 4 格内有 path/35）、`town_density_report`（装饰密度 ≥25% 或打印量化值）、`footprint_no_overlap`（建筑 fp 膨胀 1 格两两不相交，城已有，推广到镇） | 替代坐标隐式依赖（立项书 §六.2 要求） |
| 预算新增 | `prop_node_budget`：全图 building/装饰 prop 节点总量打印+上限告警（见 §3.7） | 现行只监控 TownDemoKit 单区 |

### 3.6 执行顺序契约（必须遵守，P0 踩坑已证）

1. override 写入（平整/铺路/垄行）**必须先于 chunk 预载**——镇生成位于 `_generate_towns` 原位置（chunk 初始加载前），天然满足
2. `_register_town_clearance` 在建筑落位后立即调用（树抑制净空）
3. 镇生成消费的可达集是第 202 行快照——**不改**（ferry/镇选址仍在 `_generate_towns` 内、demo kit 接线点之前）
4. `_ensure_connectivity`/`_ensure_corridor_width` 仍在铺设末端，重排后若 carve 切穿新布局 → M1 截图走查专门检查

### 3.7 性能预算

- 现状：全图建筑 prop ≈535 节点（城 27×5 + 镇 60~70×5 + 门派 15×5）
- v4 外推：镇装点全铺开 ≈+700~770、城 ≈+440、门派 ≈+75 → 合计 ≈**1750~2500 节点**（2 节点 prop 占大头）
- 对策：①城/门派装点密度分档（镇 ≥25%、城 ≥20%、门派核心 ≥18%）；②围栏 32px 双格单位（样板区已验证，prop 数减半）；③全图 prop 计量断言+上限 3000；④chunk 加载半径内 prop 才可见（现机制已按 chunk 加载，天然裁剪）
