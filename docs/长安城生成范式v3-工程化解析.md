## 0. 素材体系实测校正（对 ChatGPT 规范的修正）

ChatGPT 仅见 4 张表，按 768px 宽推断「48×48 核心 Tile」。实测（放大裁片+既有 16px 切片管线验证）：

- **纹理网格 = 16px**：砖缝/瓦楞/地面纹样全部 16px 对齐；本项目 TileMap 16px 网格正确，不改。
- **组装块 = 48px（16 的 3 倍）**：大件 prop（建筑/桥/门楼）按 48px 块对齐摆放，即 ChatGPT 所称"核心 Tile"。
- 结论：**保留 16px 世界网格**，采纳规范其余全部纪律（禁非整数缩放/禁重绘素材/manifest-first/道路先行/prefab/密度/截图验收）。

## 1. 素材范式（工程化解析 manifest-first）

1. **一切素材先入清单再使用**：`tools/import_sckr_changan.py` 是唯一切片入口（清单坐标=源图像素 l,t,r,b），每个条目有语义名+分类；生成器**只能引用已切片名字**，禁止临时写像素窗口。
2. **manifest 产物**：`data/sckr_manifest.json`（名字/源表/区域/分类/像素尺寸/foot 格数）= 全项目素材数据库；联络表 `docs/shots/pack_jingcheng/slice_contact.png` 供目检修框。
3. **尺寸纪律**：prop 按原生像素整窗切片+alpha 修边，禁拉伸禁重绘；tile 条目 16px 整窗不修边。
4. **建筑 prefab 纪律**：每栋建筑=「foot 矩形（T_FOOT 透明碰撞）+ sprite 底边中点锚」，檐宽匹配 foot（~95px 檐→foot 4×2）；门前景格=传送门锚。

## 2. 地图范式（道路先行 + 无空地 + 密度）

拓扑（街网/坊墙/门洞/渠缝）由 `data/changan_city.json` 冻结——BFS/宵禁/传送门/锚点全锚定其上，**本范式不动拓扑，只重铸表面与密度**：

1. **道路先行**：朱雀御道(9 宽中轴 3 石板)/主干街(5)/坊内十字街(2)/巷——等级既有，保持。
2. **无空地纪律**：坊墙内禁止裸草——坊内地坪=夯土人字纹(74)/方砖(101)，绿化只以「园池口袋」形式点缀（草+树+条凳/井）。
3. **连续街面**：坊四边临街面（面朝街缝）立店排/摊排（前店后院坊市肌理），密度 70%→90%；坊门门楼/市门楼保留。
4. **坊内肌理**：每半坊 2×2 里坊单元（院墙圈+民居+园口袋）背靠背排列，留 1 格巷；地标（2 层楼/殿）破天际线。
5. **闹市**：两市摊位 8→20+（雨棚摊/食摊车/货担），马车/轿子停市边，人群 NPC 巡市；钟鼓楼既有。
6. **宫城**：空旷丹墀→中轴廊庑建筑群（太极殿+两仪殿/东宫+配殿廊+金亭+宫门楼+石狮+香炉+仪仗幡），丹墀前platform白石台基。
7. **水系**：渠水换江南蓝(112)+两岸岸石(111)+拱桥 prop 压桥格+渠柳；**南护城河**（墙外 3 宽水带+岸石+桥+船 prop）点题概念图水乡。
8. **街道道具**：朱雀街灯既有加密；主干街口红灯笼/告示牌/拴驴/石灯；停车马（马车/牛车/轿子）于街缘。

## 3. 渲染与碰撞范式

- prop 一律 z=2 + 底边中点锚（递归 y-sort 与玩家自然互遮挡）；拱桥/牌坊类「可穿行 prop」不占 collision，靠 y-sort 形成桥洞/门洞遮挡。
- foot 占格=T_FOOT(102) 全碰撞；水面=112（碰撞）；岸石=111（可走）。
- 新瓦片注册：`tileset_generator.gd` textures 表 + 双份 COLLIDING 数组（tileset_generator 与 changan_generator）必须同步。

## 4. NPC 范式

- 城内 NPC 8→24：市井人群（两市 idle/wander 于摊位锚点）+ 宫城仪仗守卫 + 街面行人；legs=[state,ref,start,end,off] 复用既有日程制；新增锚点 `market:西市`/`market:东市`/`palace_south`。
- 纪律：NPC 不堵 2 格净宽通道（摊位/道具布点避让中巷与门洞）。

## 5. 验收范式（每里程碑必跑）

1. `python tools/import_sckr_changan.py`（改切片后）→ 联络表目检
2. `godot --headless --path . res://tools/probe_changan.tscn`（结构断言全绿）
3. `python tools/regress_world.py`（开放世界无回归）
4. `python tools/run_changan_e2e.py windowed`（真实主场景链路+样张重出）
5. **黄金 5 问**：①像游戏场景还是概念图？②玩家知道往哪走吗？③素材同属一个游戏吗？④是现有素材合理组合吗？⑤玩家走进去场景成立吗？
6. **一票否决**：素材拉伸/像素模糊/建筑漂浮/道路断裂/场景像空地或随机拼贴——出现即返工。

## 6. 第三轮通病方法论（2026-09-07，四类红框根治后沉淀）

> 来源：用户四条通病反馈（桥接水/巨型轿马堵路/坊宅堆叠无层次/像素太大），vision 子代理逐图取证→代码根治→同点位截图 vision 复验全 PASS。

1. **比例纪律（禁英雄物件）**：可移动道具（车/轿/驴）高度 ≤ 相邻建筑檐口 1/2。SCKR 车轿族切片原生 96px 高（与 94px 城门楼等高），一律 `_spawn_prop(..., 0.5)` 半缩后使用；整数缩放不糊，非整数缩放仍禁。cart_horse_a(192px) 半缩后仍与门楼等高——直接下架。
2. **摆位纪律（路缘+避路口）**：路面道具只停主路最外 2 格车道，禁中轴；生成点必须先做横街带 band 检查（环路带+主干街缝 row_y(j)±main_s），路口禁停；宫门/门楼 ±3 格内自动避让（_dressing_cell_free 兜底）。
3. **桥跨纪律（禁"接水"）**：桥 prop 切片禁止内嵌画死的水面（`bridge_arch_stone` 整块下 45% 是水——重切 `bridge_arch_stone_deck` 96×58 只留桥面+拱身）；锚定规则=deck 顶对齐北岸岸顶（`bottom = wy0*16+58`），下方露真实水瓦；门→引道（草带缺口铺 T_MAIN_ROAD）→桥→对岸全程瓦片无缝。
4. **横向间距算术对账**：同带摆放列表必须先算锚点坐标查重——本轮 willow 锚列表 (px+8) 与石灯 cx-6 恰好完全同点叠放（红框"树和石墩重叠"根源）。规则：同带 props 互距 ≥4 格、大 sprite（≥96px）距桥轴/门轴 ≥12 格。
5. **院落范式（禁散楼平铺）**：坊内最小单元=9×9 四合院（围墙 100/105 围合 + 北正房 4×2 + 东西厢房 2×2 + 南月洞门 2×2 + 方砖庭院 T_PAVE + 门前甬道接巷），每坊 2×2 院背靠背，避坊内十字街（竖街 gx0±1/横街 gy0±1 各让格）；四院轮换 宅/宅/园池院/地标院（楼阁破天际线）。墙只覆"巷土格且无装饰"，压不上就留口=自然豁口，不强塞。
6. **视距纪律**：城内相机 zoom 3→2（整数比，世界像素=2屏像素不糊），单体建筑占屏从 ~25% 降到 ~5%，一眼一坊组群；开放世界维持 zoom 3 不变（city_visit._set_camera_limits 分支）。
7. **视觉证明流程（强制）**：改前 vision 子代理分析反馈图逐项取证（位置/颜色/比例证据）→ 代码修复 → 同点位 CHANGAN_SHOT 截图 → vision 子代理 PASS/FAIL 复验；禁纯推理收工。E2E 探针断言随实现同步更新（本轮：底边锚校验带 scale、拱桥 prop 认 deck 版切片名）。
